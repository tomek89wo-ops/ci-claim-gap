## What the misses had in common

Every single false positive was the same mistake wearing a different hat:
**something that IS a test, which the tool did not recognise as one**, or
**something that is NOT verification, which the tool treated as if it were.**

- `cargo nextest run` — the default Rust runner. `\btest\b` cannot match inside
  "nextest", so zed's three full test jobs were invisible and the tool accused
  a 60k-star project of never testing on Windows or macOS.
- `namespace-profile-mac-large` — a Mac that is not called `macos`.
- `codeql.yml::analyze` — a security scanner is neither a build nor a shipment,
  so it cannot support "ships there and never tests there".
- `Run integration tests and store durations` — runs tests to **measure** them.
  `|| true` is correct when you want the timing even from a failure.
- `if: runner.os == 'Linux'` beside `if: runner.os != 'Linux'` — full coverage
  written as two complementary halves.

## The number that matters

**45 repositories scanned across three days. One finding worth a maintainer's
time.** That ratio is the point of the tool, not a disappointment: a check that
fires on every repository is measuring nothing. It is also why every correction
above is pinned by a test — the failure mode that destroys a tool like this is
not missing a defect, it is accusing a project that was doing it right.
